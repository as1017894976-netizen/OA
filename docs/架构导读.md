# 空模板架构导读

这个分支（`claude/skeleton`）是 RuoYi Office 开源版去掉所有业务模块后的空模板：只保留登录、工作台、**系统管理**和**基础设施**，
用来读源码、理解整体架构。OA、人力、流程、商城、CRM、ERP、AI、IoT 等业务代码都已删除，完整版仍在 `master-jdk17` 分支。

前端在另一个仓库 OA-vben 的同名分支 `claude/skeleton`。

## 一、跑起来

```sql
CREATE DATABASE `ruoyi-office` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

```bash
# 1. 数据库：56 张表，只有系统管理和基础设施的数据
mysql -uroot -p --default-character-set=utf8mb4 ruoyi-office < sql/mysql/skeleton/skeleton-init.sql

# 2. 后端（JDK 17+，需要 MySQL 和 Redis；连接信息在 yudao-server/src/main/resources/application-local.yaml）
mvn clean package -Dmaven.test.skip=true -pl yudao-server -am -Pboot
java -jar yudao-server/target/yudao-server.jar --spring.profiles.active=local

# 3. 前端（OA-vben 仓库，Node 20+，pnpm 10）
pnpm install
cd apps/web-antd && pnpm dev        # 打开 http://localhost:5666，admin / admin123
```

## 二、整体结构

```
浏览器 ──> Vben 前端 (apps/web-antd) ──HTTP /admin-api/**──> yudao-server (Spring Boot, 端口 48080)
                                                                │
                                         ┌──────────────────────┼──────────────────────┐
                                  yudao-module-system     yudao-module-infra      （以后的业务模块）
                                  用户/角色/菜单/部门/      文件/配置/代码生成/
                                  租户/字典/日志/通知        接口日志/监控
                                         └──────────┬───────────┘
                                             yudao-framework（各种 starter）
                                                    │
                                              MySQL + Redis
```

后端是**模块化单体**：`yudao-server` 本身几乎没有代码，只是一个启动壳，在 `pom.xml` 里引入哪些 `yudao-module-xxx-server`，
就有哪些功能。启动类 `yudao-server/src/main/java/cn/iocoder/yudao/server/YudaoServerApplication.java` 扫描
`cn.iocoder.yudao.server` 和 `cn.iocoder.yudao.module` 两个包。

| 目录 | 作用 |
|---|---|
| `yudao-dependencies` | 统一管理所有第三方依赖的版本，只有一个 pom |
| `yudao-framework` | 技术底座，每个 starter 解决一类通用问题（见第四节） |
| `yudao-module-system` | 系统管理：登录认证、用户、角色、菜单权限、部门岗位、租户、字典、通知、短信邮件、操作日志 |
| `yudao-module-infra` | 基础设施：文件存储、参数配置、代码生成、数据源、接口访问/错误日志、Redis 与服务监控、WebSocket |
| `yudao-server` | 启动壳和配置文件（`application.yaml`、`application-local.yaml`） |
| `sql/mysql/skeleton` | 空模板的数据库脚本 |

每个业务模块拆成两个子模块：

- `xxx-api`：给**其它模块**调用的接口和 DTO，例如 `system-api` 里的 `AdminUserApi`、`DeptApi`。模块之间只依赖对方的 api，不直接用对方的 Service。
- `xxx-server`：模块自己的实现。

## 三、跟着一个请求走一遍：岗位管理

「系统管理 → 岗位管理」是最小的增删改查，适合当作第一个读的功能。下面是打开列表页时经过的文件。

**前端**（OA-vben 仓库 `apps/web-antd/src`）

1. `views/system/post/index.vue`：页面。用 `useVbenVxeGrid` 画表格，用 `useVbenModal` 弹出 `modules/form.vue` 新增/编辑。
   按钮上的 `auth: ['system:post:create']` 决定按钮是否显示。
2. `views/system/post/data.ts`：表格列、搜索表单、编辑表单的定义，页面和配置分开写。
3. `api/system/post/index.ts`：`getPostPage()` 发出 `GET /admin-api/system/post/page`。
4. `api/request.ts`：所有请求都经过这里，自动带上 `Authorization: Bearer <token>` 和 `tenant-id` 请求头；
   token 过期时用 refresh token 自动续期；开启接口加密时在这里加解密。

**后端**（本仓库 `yudao-module-system/yudao-module-system-server/src/main/java/cn/iocoder/yudao/module/system`）

5. 过滤器先处理请求：`TokenAuthenticationFilter` 校验 token 并把登录用户放进上下文，`TenantContextWebFilter` 读取 `tenant-id`。
6. `controller/admin/dept/PostController.java`：`@RequestMapping("/system/post")`。方法上的
   `@PreAuthorize("@ss.hasPermission('system:post:query')")` 做权限校验，`@ss` 是 `SecurityFrameworkServiceImpl`，
   它查「当前用户的角色 → 角色拥有的菜单 → 菜单上的权限标识」。
7. `controller/admin/dept/vo/post/`：入参出参对象。`PostPageReqVO` 是查询条件，`PostSaveReqVO` 是新增/修改，`PostRespVO` 是返回给前端的。
8. `service/dept/PostServiceImpl.java`：业务逻辑和校验（例如岗位编码不能重复），出错时抛 `ServiceException`，错误码定义在 `system-api` 的 `ErrorCodeConstants`。
9. `dal/mysql/dept/PostMapper.java`：继承 `BaseMapperX<PostDO>`，单表增删改查和分页不用写 SQL。
10. `dal/dataobject/dept/PostDO.java`：对应 `system_post` 表，继承 `BaseDO`（自带创建人、创建时间、更新人、更新时间、逻辑删除）。
11. 返回值统一包成 `CommonResult`：`{"code": 0, "msg": "", "data": ...}`，异常由 `GlobalExceptionHandler` 转成同样的格式。

记住这条线：**页面 → api → Controller → Service → Mapper → DO → 表**。所有功能都是这个套路，新功能也照这个结构写。

## 四、框架里的几个关键机制

| 机制 | 在哪 | 一句话 |
|---|---|---|
| 登录与令牌 | `system` 的 `controller/admin/auth`、`service/oauth2`；框架 `starter-security` | 登录后发 access token 和 refresh token，存在 `system_oauth2_access_token` 表和 Redis |
| 菜单与按钮权限 | `system` 的 `service/permission`；框架 `SecurityFrameworkServiceImpl` | 菜单表 `system_menu` 同时存目录、页面和按钮，按钮的 `permission` 字段就是 `@PreAuthorize` 里的标识 |
| 多租户 | 框架 `starter-biz-tenant`（`TenantDatabaseInterceptor`） | 继承 `TenantBaseDO` 的表会自动在 SQL 上加 `tenant_id = ?`，业务代码不用管 |
| 数据权限 | 框架 `starter-biz-data-permission` | 按角色的数据范围（本部门、本部门及以下、自定义等）自动给查询加部门条件 |
| 统一返回与错误码 | 框架 `yudao-common`（`CommonResult`、`ServiceException`）、`starter-web`（`GlobalExceptionHandler`） | 前端只看 `code` 是否为 0 |
| 操作日志 | 框架 `@LogRecord` 注解，见 `AdminUserServiceImpl` 等 | 改数据时记录谁在什么时候改了什么 |
| 字典 | `system` 的 `dict`；前端 `DictTag` 组件 | 下拉选项、状态标签统一从字典表取 |
| 代码生成 | `infra` 的 `codegen`；前端「基础设施 → 代码生成」 | 选一张表，生成上面第三节那一整套前后端文件 |

其它 starter：`mybatis`（MyBatis-Plus 与分页）、`redis`（缓存）、`excel`（导入导出）、`mq`（消息队列）、`job`（xxl-job 定时任务客户端）、
`websocket`、`monitor`（链路追踪）、`protection`（限流、幂等、分布式锁）、`env`（多环境）。

## 五、前端结构（OA-vben 仓库）

这是 Vben Admin 5 的 monorepo，**只需要看 `apps/web-antd`**，`packages/` 是 Vben 框架本身（布局、表格表单封装、权限、请求、国际化），平时不用改。

| 目录 | 作用 |
|---|---|
| `apps/web-antd/src/views` | 页面，按「模块/功能」分目录，和后端菜单的组件路径一一对应 |
| `apps/web-antd/src/api` | 接口函数，按模块分目录，和后端 Controller 一一对应 |
| `apps/web-antd/src/router` | 路由。`preferences.ts` 里 `accessMode: 'backend'`，菜单和路由都由后端返回，登录后调 `/system/auth/get-permission-info` 拿到 |
| `apps/web-antd/src/adapter` | 把 Ant Design Vue 组件接入 Vben 的表单（`form.ts`）和 vxe-table 表格（`vxe-table.ts`） |
| `apps/web-antd/src/store` | 登录状态等全局状态（Pinia） |
| `apps/web-antd/src/components` | 项目里的通用组件：字典标签、上传、富文本、Cron 表达式等 |

**菜单驱动页面**：在「系统管理 → 菜单管理」新增一个菜单，填组件路径 `system/post/index`，前端就会去加载
`views/system/post/index.vue`。所以新页面要做两件事：写 vue 文件，再在菜单管理里登记。

## 六、以后加业务模块

1. 照 `yudao-module-system` 的样子新建 `yudao-module-xxx`（含 `-api` 和 `-server`），在根 `pom.xml` 的 `<modules>` 和 `yudao-server/pom.xml` 的依赖里加上它。
2. 建表，然后用「基础设施 → 代码生成」生成 Controller 到前端页面的一整套代码，再在上面改业务逻辑。
3. 在菜单管理里加菜单和按钮权限，给角色授权。

完整版里的 OA、人力等模块（`master-jdk17` 分支）就是这样接进来的，读懂空模板后可以对照着看。

## 七、和完整版相比删了什么

- 后端：`yudao-module-` 下的 oa、hrm、bpm、asset、wms、member、pay、report、mp、mall、crm、erp、ai、iot，以及只服务于业务单据的 `yudao-common-server`、云版网关 `yudao-gateway`；
  `application.yaml` 里的工作流、AI、商城、IoT 配置；用户管理里同步员工档案的代码。
- 前端：上面这些模块的页面、接口和路由，Element Plus、Naive UI、TDesign 等其它 UI 版本的 app，依赖流程的「单据表单」「附件列表」组件和首页「任务列表」组件。
- 数据库：业务表、业务菜单和字典；另外去掉了两个原版就打不开的菜单（定时任务、代码生成案例）。具体见 `sql/mysql/skeleton/cleanup.sql`。
